01 / WHAT YOU ADD TO YOUR PROJECT

A.R.I.A. combines a local Python framework with AI-agent working rules. It compiles project context, defines a development contract and verification plan, then validates result artifacts. It is designed for changes affecting multiple components, layers and critical flows.

You

A defect is found. What comes next?

A.R.I.A. working rules require a report with severity, evidence, impact and root cause. The AI agent fixes the cause with architecture, data and operations in mind, then reruns affected and neighboring checks. An unproven cause remains a hypothesis.

02

03

Required classes, scenarios, proof excerpts and applicable metrics are checked before closure.

04

Requirement traceability

In standard/deep build, every requirement links to completed tasks and code; every acceptance criterion links to verified evidence.

The engine rejects completion when…

  • a check fails;
  • a required test class is missing;
  • code changed after verification;
  • output or an evidence artifact was altered;
  • a requirement has an unproven acceptance criterion;
  • required independent review is missing.

The engine validates formal links and execution facts. AI review and developer acceptance assess the semantic completeness of requirements, tests and the solution.

Before you start.

Can a beginner use it?+

Yes, if you are ready to work with project files, commands and test results. A.R.I.A. provides structure: what to clarify, what to change and how to prove the outcome. You still need to understand and evaluate technical decisions and final acceptance.

Which projects can it verify?+

Projects with a defined stack, verification commands, context and outcome criteria. The planner considers API, UI, workers, storage, migration and hardware risks, among others. External services and devices require the corresponding test environment.

Who writes code and tests?+

Codex or Claude Code does the engineering work. A.R.I.A. defines context and obligations, runs configured checks through aria verify and validates evidence. It combines an AI tool with a local engine.

How are errors discovered?+

Through code analysis, independent review and risk-appropriate checks: functional, integration, end-to-end, negative, load and failure tests. The engine rejects insufficient or inconsistent evidence. Results depend on the quality of requirements and the checks themselves.

Do I need a separate server?+

Not for local work. The team Coordinator runs on the owner’s PC and uses GitHub. AI-provider access and data transfer depend on your chosen tool and its settings.

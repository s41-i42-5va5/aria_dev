Engineering mechanisms.
Practical benefits.

Feature Contract

Define what “done” means

Outcome, requirements, acceptance criteria, plan and task graph. In standard/deep, the contract is fixed before code changes.

Project Context

Memory across sessions

Compact state, decision history and a system map. The map is checked against Git and the working tree.

EvidenceBundle

Tests with an inspectable record

Execution receipts and raw command output. If code changes after verification, the previous evidence is no longer enough.

Governance & Preflight

Rules before changes

Checks for the baseline, task assignment and permitted operation. Inconsistent state requires recovery.

Signed State & CI

Verifiable provenance

Signed state and imported CI results bound to a run, commit and contract. Protection against replaying a result.

Scope & Leases

Boundaries for team work

Tasks, assignees, dependencies and file scopes. A conflicting scope blocks another task from starting.

ONE TASK / FOUR CLEAR STEPS

“Add a CSV export.”
What does “done” mean?

An illustrative example: you choose the criteria. A.R.I.A. helps make them part of the workflow and connect them to checks.

01

Define the result

Which fields should be exported? Is UTF-8 required? Who can download the data? These are requirements, not guesses for AI to make.

02

Check the affected code

Identify the export handler, data model and access check. Record dependencies and the plan before implementation.

03

Collect evidence

Run the specified checks for encoding, content and access. Save the output and link each result to its requirement.

04

Accept against the criteria

Identify what is proven and what still needs a real environment check. The team workflow also confirms the merge and required checks.

QUESTIONS AND ANSWERS

Before
you begin.

Do I need programming experience?+

A.R.I.A. can help beginners, but involves project files and commands. The guide explains package verification and installation. You still need to understand and evaluate requirements, tests and final acceptance.

Is it an AI model or an editor?+

It is a local Python framework for the development workflow. Your chosen AI tool writes the code. A.R.I.A. connects that work to requirements, context and evidence.

Do I need an always-on server?+

Not for local work. In a team, the Coordinator runs on the owner’s PC. If it stops, confirmed GitHub events wait for synchronization; processing continues after it starts again.

Where does my data live?+

Product source, project documents and execution data have separate boundaries. Team work uses GitHub. Data sent to an AI provider depends on Codex or Claude and their settings.

What does successful verification mean?+

The specified conditions were met on a particular code state. Requirements and test coverage still matter. It does not replace checks of external APIs, devices or the product in its real environment.

Can I inspect it and contribute?+

Yes. Source, tests and documentation are available in the open GitHub repository. Explore the architecture, integrations and command examples before changing your project workflow.

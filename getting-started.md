# Знакомство с // A.R.I.A. 1.5.5

// A.R.I.A. — локальный framework управления разработкой и проверкой цифровых продуктов через AI-инструменты. Он связывает задачу, контекст репозитория, требования, выполнение, проверки и принятие результата.

Скачайте нужную поставку на [странице релиза 1.5.5](https://github.com/s41-i42-5va5/ARIA/releases/tag/v1.5.5) и распакуйте архив в отдельную папку. Там же доступны контрольные суммы. [Исходники и документация](https://github.com/s41-i42-5va5/ARIA) открыты для изучения.

## Codex

Codex должен быть установлен и авторизован отдельно. В папке поставки `1.5.5 for Codex` последовательно выполните:

```text
CHECK_RELEASE.cmd
INSTALL.cmd
RUN_ARIA.cmd doctor
RUN_ARIA.cmd --help
```

Продолжайте только после успешной проверки целостности и диагностики. Следуйте полной `ИНСТРУКЦИЯ.md` внутри поставки для подключения проекта и настройки доступа.

## Claude Code

До установки должны быть установлены и авторизованы Claude Code, а также поддерживаемый Git Bash или WSL. Они не входят в поставку // A.R.I.A.

В папке `1.5.5 for Claude` последовательно выполните:

```text
CHECK_RELEASE.cmd
INSTALL.cmd
RUN_ARIA.cmd claude status
RUN_ARIA.cmd doctor
```

Installer устанавливает skill `aria-project` и защитный PreToolUse hook для текущего пользователя. После установки перезапустите Claude Code и следуйте полной инструкции поставки. Hook является дополнительным механизмом контроля, а не изоляцией на уровне операционной системы.

## Командная работа

// A.R.I.A. Control использует один GitHub-репозиторий с ветками `main`, `dev`, `work/<github-username>` и `aria-control`. Coordinator работает локально на ПК владельца. Живые операции требуют интернета и настроенного GitHub-доступа. Настройка GitHub App и прав участников описана в полной инструкции поставки.

## Что проверять в собственном окружении

- Целостность поставки и результат диагностики.
- Подключение нужного репозитория и корректность границ кода, документов и runtime.
- Интеграцию с выбранным AI-инструментом.
- Реальное выполнение проверок продукта и сохранение доказательств.
- Для командного сценария — роли, задачи, PR, обязательные checks и merge с реальными аккаунтами.

Проверка framework не подтверждает готовность конкретного продукта, внешнего API или устройства. Критерии приёмки и проверка в реальном окружении задаются отдельно.
